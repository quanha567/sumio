# Sage & Forest --- Personal Finance Design System v1.0

**Product:** Personal Finance\
**Visual direction:** Friendly Personal Finance\
**Stack:** HeroUI v3 + Tailwind CSS v4\
**Platforms:** Web + Mobile\
**Themes:** Light + Dark\
**Status:** Proposed design-system baseline; validate against the
installed HeroUI version before production.

---

## 1. Design decisions

- **Primary brand:** Forest Green `#245C45`
- **Secondary brand:** Sage `#7DA58B`
- **Neutral page background:** Mist `#F5F6F4`
- **Default surface:** White `#FFFFFF`
- **Dark background:** `#171D19`
- **Dark accent:** `#A7D2B3`
- **Typography:** Inter, with tabular numerals for money values.
- **Architecture:** primitive tokens → semantic tokens →
  financial-domain tokens.
- **Principle:** Brand color and financial meaning must remain
  separate. Green must not be used to mean "income" everywhere by
  default.

### Design principles

1.  Clear, friendly, and trustworthy; avoid childish decoration.
2.  Neutral surfaces keep financial data easy to scan.
3.  Forest Green identifies the brand and primary actions.
4.  Sage supports charts and secondary emphasis; do not use it as small
    text on white without checking contrast.
5.  Income, expense, transaction status, and dangerous actions have
    separate semantic tokens.
6.  Color is never the only indicator of meaning; pair it with labels,
    icons, or text.
7.  Light and dark themes must both be tested with real component
    combinations.

## 4. Financial-domain tokens

Finance tokens are independent of brand tokens. A transaction's
direction and its processing status are separate concepts.

---

Token Light Dark Meaning

---

`finance-income` `#18794E` `#6DD8A2` Income inflow

`finance-expense` `#B42318` `#FF938B` Expense outflow

`finance-neutral` `#3E4840` `#D5DED6` Balance/neutral
amount

`finance-pending` `#925C10` `#F5C36B` Pending transaction

`finance-investment` `#326747` `#A7D2B3` Investment-related
item

`finance-transfer` `#175B83` `#80C9F2` Transfer
-------------------------------------------------------------------------------

Rules: - Income/expense describe cash-flow direction, not transaction
state. - Pending/completed/failed describe transaction state, not
cash-flow direction. - Use icon/label plus color; never use color alone
to encode a state. - Validate all text/background combinations,
including badges and chips, before shipping.

## 6. Theme provider example

If the project uses `next-themes` and CSS class-based dark mode:

```tsx
"use client";

import { ThemeProvider } from "next-themes";

export function AppThemeProvider({ children }: { children: React.ReactNode }) {
  return (
    <ThemeProvider attribute="class" defaultTheme="system" enableSystem disableTransitionOnChange>
      {children}
    </ThemeProvider>
  );
}
```

If using `data-theme`, change `attribute="data-theme"` and ensure the
theme provider and CSS selectors use the same convention. Confirm how
the installed HeroUI version handles theme selection and CSS variables;
avoid competing theme systems.

## 7. WCAG 2.2 AA contrast requirements

### Thresholds

- Normal text: at least **4.5:1**.
- Large text: at least **3:1**.
- Essential UI boundaries and graphical indicators: generally at least
  **3:1** against adjacent colors under the non-text contrast
  criterion.
- Focus indicators must be visible and tested against adjacent
  surfaces.
- Disabled controls have WCAG exceptions, but should remain legible
  where practical.

### Representative contrast pairs

The following are intended as design checks. Recalculate with an
automated contrast checker against the final CSS values and component
states before release.

---

passes on the page canvas may fail on a card, badge, or hover surface.

### Contrast rules for implementation

1.  Do not put white small text on Sage `#7DA58B`.
2.  Use Forest `#245C45` for primary Light-mode CTA with white text.
3.  In Dark mode, use `#A7D2B3` for the accent fill and `#17241B` for
    its text.
4.  Do not assume the status color is suitable for a filled badge. Use
    the dedicated `*-subtle` background and verify the
    foreground/background pair.
5.  Placeholder text must not replace an input label.
6.  Use `border-strong` for meaningful boundaries where the default
    border does not provide sufficient contrast.
7.  Test focus, hover, active, selected, disabled, validation, charts,
    and all surface combinations in both themes.
8.  Pair financial colors with text/icons; never rely on color alone.

## 8. Component usage rules

### Buttons

- Primary: `accent` + `accent-foreground`.
- Secondary: `surface` with `border` and `foreground`.
- Tertiary/ghost: transparent background with `foreground`.
- Destructive: `danger` + `danger-foreground`.
- Focus ring: `focus-ring`.
- Disabled: `disabled` + `disabled-foreground`.

### Cards and surfaces

- Page canvas: `background`.
- Default card: `surface`.
- Secondary panels: `surface-secondary`.
- Elevated menus/dialog content: `surface-raised`.
- Borders: `border`; important input/component boundaries:
  `border-strong`.

### Money display

- Use tabular numerals to prevent digit widths from shifting.
- Format currency using locale-aware APIs,
  e.g. `Intl.NumberFormat("vi-VN", { style: "currency", currency: "VND" })`.
- Do not use JavaScript floating-point numbers as the authoritative
  representation for monetary calculations. Use integer minor units
  where appropriate or a decimal arithmetic library.
- Keep transaction direction, transaction status, and account balance
  as separate concepts.
- When balances are hidden, preserve layout stability and provide an
  accessible toggle label.

### Responsive behavior

- Desktop: sidebar navigation, summary cards, detailed transaction
  table.
- Tablet: compact navigation and fewer simultaneous dashboard columns.
- Mobile: bottom navigation or compact navigation, stacked summary
  cards, transaction list instead of a wide table.
- Test widths at 320, 375, 768, 1024, and 1440 px.
- Use responsive spacing and avoid making dense financial tables the
  default mobile experience.

## 10. Final design-system decisions

- **Brand:** Forest Green `#245C45`.
- **Secondary:** Sage `#7DA58B`, with contrast-aware usage.
- **Light background:** `#F5F6F4`.
- **Default surface:** `#FFFFFF`.
- **Dark background:** `#171D19`.
- **Dark accent:** `#A7D2B3`.
- **Typography:** Inter with tabular numerals for financial data.
- **Token architecture:** primitive → semantic → financial domain.
- **Component stack:** HeroUI + CSS variables + Tailwind CSS v4.
- **Release gate:** automated contrast checks and manual visual
  verification in both themes.

**Implementation note:** This is a proposed application token layer, not
a guarantee that all variables map automatically to HeroUI. Check the
installed HeroUI version and map its documented theme variables
explicitly before shipping.
